# 模型适配

同一套四步选择，不同模型的喂法不同。**不要把四种格式拼在一起发。**

## 网页端「一键出图」走的是哪几条路（2026-10-08 实测）

出图工作流里有 5 个模型项，**能不能真的一键出图各不相同**。
按通道分三类，界面上用按钮前的圆点标出来：

| 通道 | 模型 | 一键出图 | 说明 |
|---|---|---|---|
| `keyed` | GPT-Image 2、Nano Banana 2.1、Flux | ✅ 需你自己的 API key | 模型名在这一路才真正生效 |
| `anon` | Sana · 免 key | ✅ 不要钱 | 约一半请求被限流挡掉 |
| `manual` | Midjourney | ❌ | **没有公开出图 API**，只给「复制标签版 + `--ar` + 官网入口」 |

### 为什么匿名通道不能选Flux / GPT-Image

`GET https://image.pollinations.ai/models` 只返回 `["sana"]`。

用 `flux` / `turbo` / `sana` / `gpt-image-2` / `nano-banana` 五个名字
请求同一提示词、同一 seed，**返回文件的 md5 完全相同**。
即`model` 参数在这条路上是失效的。

所以那一项在界面上叫「**Sana · 免 key**」而不是「Flux」。
写成 Flux 就是骗用户 —— 而用户会拿这张图去商用。

### 走keyed 通道要知道的

-端点是 `POST https://gen.pollinations.ai/v1/images/generations`，
  无 key 返 401。CORS 预检实测通过（`Access-Control-Allow-Origin: *`，
  允许 `authorization` 头），所以浏览器里能用。
- key 走 `Authorization: Bearer` 头，**不要放进 URL** ——
  URL 里的 key 会进浏览器历史、截图与 Referer 头。
- **Nano Banana 2.1 在官方清单里标了 `paid_only: true` 且 `health: down`**，
  可能要付费额度且当前处于故障状态。这条写在界面上，不埋在 tooltip 里。
- keyed 通道按 token 计费，所以**抽卡在 keyed 通道上是禁用的** ——
  一次抽 6 张等于用户没看见就花了六份钱。

### 免key 通道的限流不是时间窗口

官方文档写「匿名用户每 15 秒 1 个请求」，但实测（同一 IP 顺序请求）：

| 间隔 | 结果 |
|---|---|
| 3s | 200 402 402 402 |
| 15s | 402 402 200 |
| 25s | 402 200 402 200 |
| 35s | 402 200 402 200 |
| 60s | 402 200 200 |

**加长间隔并不提高成功率**，成功与否与间隔基本无关，约一半请求被拒
（更像一个共享配额池）。所以 Agent 批量出图必须**退避重试**
（1 次 → 16s → 32s → 64s），只发一次的话 4 张里必有 2 张失败。

### Agent 自己跑图时不要依赖网页端那一路

公共通道限流、随时变更，且模型与参数不由本库控制。
**先把正文拿到，再选一个你自己有账号的模型。**

## 该给哪个格式

| 模型 | 用什么 | 画幅怎么传 | 负面词 |
|---|---|---|---|
| **GPT-Image / gpt-image-2** | 完整中文或英文正文 | 正文已含比例描述，另在参数里设 | 已在正文末尾，**不要再单发** |
| **Midjourney v6 / v6.1** | 标签速用版 | `--ar 3:4` | `--no` |
| **Midjourney niji** | 标签速用版 | `--ar` | `--no` |
| **Flux.1** | 英文正文 | 参数传宽高 | 负面词可传可不传，见下 |
| **SDXL / Illustrious** | 英文正文或标签版 | 像素宽高 | 独立负面词框 |
| **NovelAI V3/V4** | 标签速用版 | 宽度数值 | 独立负面词框 |

## 三条通用注意

### 一、同一套约束不要写两遍

把英文正文和标签版拼在一起发，模型会把它理解成两个独立要求，
结果是权重混乱、输出过度饱和或过简。

**选一种。** GPT 系给正文，MJ 系给标签。

### 二、负面词在 GPT 系里已经写进正文了

本库的 `compose()` 末尾会追加禁止项（不要文字/水印/标识）。
GPT-Image 没有独立的负面词框，所以这段是正文的一部分。

**不要再单发一遍负面词列表** —— 重复约束会让模型过度压制某些元素，
常见后果是画面变得过于干净、失去细节。

### 三、画幅是参数，不是提示词

正文里写了「画幅比例 3:4」，但**工具里也要真的设成 3:4**。
只写不说，模型有概率按训练分布出方图。

网页端把这件事做实了：出图比例与正文里的画幅句**同源**。
选 16:9 时正文那句会被改写成 16:9，请求参数也是 768×432。
只改一边（正文说 3:4、请求发 16:9）等于给模型两套矛盾指令，
出哪一张不由用户决定。

出图比例是**出图工作流里的独立选项**（1:1 / 9:16 / 16:9 / 3:4 / 4:3 / 自定义），
**不跟随版式的 ratio**。版式决定画面里元素怎么摆，出图比例决定画布什么形状，
混在一起用户就没法控制自己拿到的是横图还是竖图。

### 四、水印是提示词管不住的

实测：用 `No text, letters, signage, logos or watermarks anywhere in the frame`
出图，画面右下角**仍然带 AI 生成水印**。

实测（网页端一键出图，匿名通道）：传 `nologo=true` 只关掉左上角标，
**右下角的通道标识依然在**。两者是同一类问题 —— 水印在推理阶段被加上，
不属于提示词能约束的语义层。写十遍 "no watermark" 也没用。

所以：

- 出图后必须自己裁掉或遮盖右下角
- **不要**因为写了 "no watermark" 就以为交付的图可以直接商用
- 也不要把「提示词里已经有禁止项」当作免责依据

同理，模型生成的中文字形基本是乱码 —— 版式图型里预留的空白文字区
本来就是给后期排字用的，不要指望模型写对。

## Flux 的特殊点

Flux 家族（dev / pro / schnell）对负面词的处理与 SD 系列不同：
pro 与 schnell基本不接受有效负面词，硬塞会拉低提示词与图像的贴合度。
真要抑制，只能在正文里写成正向陈述 ——
「干净的空白背景」比「no cluttered background」有效。

## 参考图垫底的边界

垫底图（image-to-image / reference）能让未适配的模型更准地还原风格，
**但它会把参考图的版权一起继承下来**。

所以：

- 参考图必须是**你自己生成的**，或明确可商用的素材
- **不要**从别人的作品截图垫底 —— 那构成直接使用他人作品
- 商用场景下这条是硬边界，不是建议

## 换模型后提示词是否还成立

**结构成立，具体措辞不一定成立。**

- 中文正文投 GPT-Image：成立，中文模型对长句中文的遵守度高
- 中文正文投 Midjourney：基本不成立，MJ 对中文的理解很弱，必须走英文
- 英文正文投 Flux：成立
- 英文正文投 NovelAI：偏长，标签版更稳

所以**每次换模型要重新跑一遍 build 拿对应格式**，不要复用上次的输出。
`forge.js build --lang en` 就是给英文模型准备的。
